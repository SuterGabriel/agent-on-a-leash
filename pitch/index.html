The Agent Card.

Your AI shopping agent gets its own Viseca card. The card carries your rules, not your money. Every payment is approved, stopped or put to you, and explained in your words.

Problem

  • To let an AI shop, you paste your real card into it. A blank cheque.
  • The only rule is a sentence inside the agent. A shop page can rewrite it.
  • When it goes wrong: a decline without a reason, a dispute on Viseca's desk.

Solution

  • Viseca issues a separate card number for the agent. The main card is never shared.
  • Rules live at Viseca, inside the mandate, and travel with every payment.
  • Approve, decline or ask in milliseconds, with the rule and the fact behind it.

Set-up and learning

  • Rules proposed from 90 days of your own shopping, with evidence. Nothing to type.
  • Correct a value, confirm with Face ID. Under a minute.
  • Your answers become rules. Stricter is one tap, looser needs your face.

Accessibility

  • Every question and every stop can be heard, not only read (ElevenLabs).
  • Answer by voice within the 120 s window. Approve still needs Face ID.
  • Set the card up by voice: the same history-based proposal, read aloud.

How we solved it

  • Deterministic engine in TypeScript. The instruction is compiled into rules; every rule keeps the words it came from. 21 guards, each returning pass, fail or unsure with the fact.
  • Merchant text is quarantined. Unicode-normalised pattern scan, facts extracted, orders to the agent flagged and quoted. Seven injection phrasings in the red team; none is ever approved.
  • State that survives. A ledger per run for rolling budgets, duplicates and retries. A state file restores the leash, feed, open asks and tokens after a crash; expired asks buy nothing.
  • Decision-bound payment tokens. Every approval issues a token for one shop, one maximum, fifteen minutes, one use. Hash-chained history with a verify endpoint.
  • Human in the loop. 120 s ask, Face ID on approve, one answer to Viseca even on a double tap. The API only tightens; loosening is a new mandate.
  • Voice channel. An ElevenLabs agent reads the question the engine composed and passes the spoken yes or no to the same endpoint. It never decides. Setup by voice proposes the same rules screen 1.3 shows.
  • Decoupled. App → our backend → worker and engine → Viseca API behind one client with an offline copy. Nothing is hard-coded to a scenario; a test fails if it were.
